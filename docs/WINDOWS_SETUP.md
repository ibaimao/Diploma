# Запуск на Windows: пошаговая инструкция

Эта инструкция относится к интерфейсу-прототипу. Supabase, база данных, Docker, Blender и ключи API для запуска текущей версии не нужны. Все задачи и дата 1 сентября — демонстрационные. Изменения не сохраняются.

## 1. Установите инструменты

1. Установите **Node.js 24 LTS** с <https://nodejs.org/>. В установщике оставьте компонент npm и добавление в PATH включёнными. Для этого проекта используем ветку Node.js 24.x.
2. Установите **Git for Windows** с <https://git-scm.com/download/win>. Стандартные настройки подойдут.
3. Установите **Visual Studio Code** с <https://code.visualstudio.com/>.
4. Используйте актуальный Edge, Chrome или Firefox.

После установки закройте и снова откройте VS Code и терминал. Если программы не находятся, перезагрузите Windows.

## 2. Откройте проект

Если репозиторий уже скачан, откройте в VS Code **Файл → Открыть папку…** и выберите папку `Diploma`. В ней должны быть `package.json`, `package-lock.json` и папка `src`.

Если репозиторий нужно скачать с GitHub:

1. На странице вашего репозитория нажмите **Code → HTTPS** и скопируйте адрес.
2. В VS Code откройте палитру команд сочетанием `Ctrl+Shift+P`.
3. Выберите **Git: Clone**, вставьте адрес и выберите папку для проектов.
4. После клонирования нажмите **Open**.

Не вводите `/workspace/Diploma` на Windows: это путь среды разработки Linux. На вашем компьютере проект может находиться, например, в `C:\Projects\Diploma`.

## 3. Откройте терминал и проверьте версии

В VS Code выберите **Терминал → Создать терминал**. Для первых запусков удобно выбрать профиль **Command Prompt / Командная строка** через стрелку рядом с кнопкой `+` в панели терминала. Он позволяет избежать ограничений PowerShell на выполнение `npm.ps1`.

Команды выполняйте по одной, нажимая Enter после каждой:

```bat
node --version
npm --version
git --version
```

Первая команда должна показать `v24.x.x`, остальные — номера установленных версий.

Убедитесь, что терминал находится в папке проекта:

```bat
dir package.json
```

Если файл не найден, перейдите в свою папку. Например:

```bat
cd /d C:\Projects\Diploma
```

Если в пути есть пробелы, используйте кавычки:

```bat
cd /d "C:\Users\Student\Documents\Study Planner\Diploma"
```

## 4. Установите зависимости

```bat
npm ci
```

Дождитесь завершения. При первом запуске нужен интернет. Команда создаёт папку `node_modules` и устанавливает версии из `package-lock.json`. Не копируйте `node_modules` между компьютерами и не добавляйте её в Git.

`npm ci` используйте также после получения изменений, если другой разработчик обновил зависимости. Добавление новой библиотеки делается через `npm install имя-пакета` по согласованию; тогда в Git должны попасть оба файла: `package.json` и `package-lock.json`.

## 5. Запустите приложение

```bat
npm run dev
```

Откройте в браузере адрес из строки **Local**, обычно:

```text
http://localhost:5173/
```

Если порт занят, Vite может выбрать следующий: ориентируйтесь на адрес, напечатанный именно в вашем терминале. Терминал оставьте открытым. После сохранения изменений в `src` страница обновляется автоматически.

Остановить сервер: нажмите `Ctrl+C` в его терминале. Если Windows попросит подтвердить завершение, введите `Y` и нажмите Enter.

## 6. Проверьте тесты, типы и сборку

В новом терминале в папке проекта выполните:

```bat
npm test
npm run typecheck
npm run build
```

Все три команды должны завершиться без ошибок. `npm test` проверяет тексты из макета, пять нужных разделов, отсутствие лишних подписей, статические отметки, структуру отдельной области задач и переключение экранов в программной DOM-среде; он не проверяет внешний вид и размеры в настоящем браузере. Последняя команда создаёт папку `dist` с готовым сайтом. Вручную открывать `dist/index.html` двойным щелчком не нужно: проверьте сборку через сервер:

```bat
npm run preview
```

Откройте адрес из терминала, обычно `http://localhost:4173/`. После изменения исходников для `preview` нужно заново выполнить `npm run build`.

## 7. Проверьте мобильный вид

В Edge или Chrome нажмите `F12`, затем `Ctrl+Shift+M`. Выберите ширину, например, 390 пикселей, и высоту 667 или 844 пикселя. Комната должна оставаться сверху, задачи — под ней, навигация — закреплена у нижнего края экрана. Общая страница не прокручивается: при недостатке места прокручивается только светлая панель задач. На компьютере весь основной интерфейс должен помещаться в окно без общей вертикальной прокрутки.

Для проверки на настоящем телефоне:

1. Подключите компьютер и телефон к одной доверенной Wi-Fi-сети.
2. Запустите `npm run dev`.
3. Откройте на телефоне адрес из строки **Network**, если Vite его показывает, например `http://192.168.1.20:5173/`.
4. Если Windows запросит разрешение для Node.js, разрешите доступ для частной сети. Не открывайте порты роутера и не используйте dev-сервер для публикации в интернете.

Адрес `localhost` на телефоне относится к телефону, а не к компьютеру. Изоляция устройств в Wi-Fi или настройки брандмауэра могут блокировать сетевую проверку; эмуляция через F12 остаётся доступной.

## Частые проблемы

| Сообщение или ситуация                                      | Что сделать                                                                                                                      |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `node` или `npm` не распознаны                              | Установить Node.js 24 LTS, перезапустить терминал, проверить PATH                                                                |
| `npm.ps1 cannot be loaded` / выполнение сценариев отключено | Выбрать Command Prompt или использовать `npm.cmd ci` и `npm.cmd run dev` в PowerShell; менять политику безопасности не требуется |
| Не найден `package.json`                                    | Открыть терминал в корне проекта, где находится этот файл                                                                        |
| `npm ci` сообщает о несовпадении lock-файла                 | Получить согласованные `package.json` и `package-lock.json` из Git; не удалять lock-файл как способ исправления                  |
| Ошибка загрузки пакетов                                     | Проверить интернет и повторить `npm ci`; не отключать проверку сертификатов                                                      |
| Сайт не открывается                                         | Проверить, что сервер запущен, и скопировать актуальный адрес Local                                                              |
| Видны старые файлы через preview                            | Повторить `npm run build`, затем обновить страницу                                                                               |

## Как работать вдвоём

- Оба разработчика запускают проект локально и устанавливают зависимости самостоятельно.
- Перед задачей получают изменения из Git и создают отдельную ветку; в основную ветку изменения попадают после проверки вторым участником.
- **Разработчик 1:** серверная часть, сохранение, будущие интеграции Supabase и 3D в `src/features/pet`.
- **Разработчик 2:** интерфейс, модули задач, календаря, таймера и статистики; будущий алгоритм планирования.
- Изменения общих типов и контрактов данных обсуждаются вместе.
- Перед передачей изменений выполняются `npm test`, `npm run typecheck` и `npm run build`.
- Пароли и будущие секреты не добавляются в исходники и Git. На текущем этапе `.env` не нужен.

## Будущее размещение на Cloudflare Pages

Публикация на этом этапе не выполнялась. После согласования размещения параметры будут такими:

- корневая папка — папка с `package.json`;
- команда установки — `npm ci`;
- команда сборки — `npm run build`;
- папка результата — `dist`;
- версия Node.js — 24.x.

Сейчас маршрутизация ограничена переключением разделов в памяти React. URL-маршруты и серверная конфигурация для них пока не нужны.
