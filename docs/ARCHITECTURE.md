# Архитектура первого каркаса

## Границы этапа

Это работающий интерфейс-прототип на React + TypeScript + Vite, без серверной части. Он отображает демонстрационные задачи, обычные и просроченные карточки, длительности и пример завершённой задачи. Локальная навигация переключает задачи и честные экраны-заглушки будущих разделов. После перезагрузки выбранный раздел сбрасывается.

Дата 1 сентября, расписание и количество завершённых задач относятся к фиксированному примеру. Это не текущая дата, не реальные пользовательские данные и не результат алгоритма.

SVG-комната нарисована в исходниках специально для этого прототипа по предоставленным визуальным референсам. Это не экспорт Blender и не интерактивная 3D-сцена. Она не требует внешнего сервиса изображений. Шрифт Nunito поставляется локально через npm; иконки — Lucide. Обращений к Google Fonts, Supabase или платёжным сервисам из приложения нет.

## Адаптивная компоновка

- Ширина больше 760 px: навигация слева, список задач по центру-слева, комната справа.
- Ширина до 760 px включительно: комната, задачи, затем нижняя навигация. Навигация расположена в потоке страницы и не закрывает карточки.
- До 380 px дополнительно уменьшаются отступы и размеры подписей.
- Минимальная поддерживаемая ширина — 320 px. Для уменьшения движения учитывается `prefers-reduced-motion`.

## Поведение демонстрации

- Навигация и кнопка возврата к задачам работают только внутри интерфейса.
- Кнопка добавления задачи отключена и имеет пояснение «Скоро».
- Отметки выполнения — статические индикаторы с текстовыми названиями для вспомогательных технологий. Они специально не сделаны кликабельными чекбоксами.
- Экран календаря не содержит фиктивного календаря; экран таймера не показывает работающий отсчёт; статистика не выдаёт примеры за собранную историю.
- Данные не записываются ни на сервер, ни в localStorage.

## Согласованный стек и последующие интеграции

| Модуль            | Сейчас                        | Позже                                                  |
| ----------------- | ----------------------------- | ------------------------------------------------------ |
| Интерфейс         | React, TypeScript, Vite       | Развитие текущих компонентов                           |
| Задачи            | Статический набор `demoTasks` | Валидация, создание, редактирование, настоящие статусы |
| Аккаунты и данные | Отсутствуют                   | Supabase Auth, PostgreSQL, RLS                         |
| Календарь         | Экран-заглушка                | Бесплатные стандартные компоненты FullCalendar         |
| Планирование      | Отсутствует                   | Отдельный модуль TypeScript с проверкой ограничений    |
| Учёт времени      | Экран-заглушка                | Pomodoro 25/5, реальные рабочие сессии                 |
| Статистика        | Экран-заглушка                | История и рекомендации на основе фактического времени  |
| Питомец           | SVG-заглушка                  | Blender → GLB → React Three Fiber / Drei               |
| Размещение        | Только локальная разработка   | Cloudflare Pages, результат сборки `dist`              |

FullCalendar, Supabase SDK, Three.js, React Three Fiber и Drei пока не устанавливаются: текущий код их не использует. Подключение этих библиотек будет частью соответствующих этапов. Не добавлены маршрутизатор, глобальное хранилище, UI-фреймворк и сервер — для текущего объёма достаточно локального состояния React.

Перед настоящим сохранением нужно разработать доменную модель: пользователь, задача, занятие, доступный интервал, запланированный блок, фактическая рабочая сессия. `DemoTask` — модель отображения, её не следует автоматически превращать в таблицу PostgreSQL: дата и время сейчас представлены человекочитаемыми строками.

Для 3D следует заменить содержимое `PetRoomPlaceholder`, сохранив отдельный модуль питомца и адаптивный контейнер. Тяжёлые GLB и WebGL-код нужно загружать отложенно; для устройств без подходящей графики сохранить иллюстрацию. Награды, монеты и аксессуары в этом этапе не реализуются.

## Ответственность команды

**Разработчик 1** отвечает за серверную часть, сохранение данных и 3D: будущий слой Supabase, миграции PostgreSQL, RLS, серверные операции, GLB и рендер комнаты.

**Разработчик 2** отвечает за интерфейс и алгоритмы: `app`, представление задач, календарь, таймер, статистику и будущий модуль планирования.

Контракты данных, расчёт фактического времени и границы серверных проверок согласуются совместно. Демо-данные нужно убрать из пользовательского потока, когда появится настоящая база.

## Требования репозитория

Источник требований — корневой [AGENTS.md](../AGENTS.md), полученный из `origin/main`. Файл сохранён без изменений. Первоначальная локальная копия репозитория отставала от main; после `git fetch origin main` правила прочитаны и каркас проверен повторно. Результат — в [AGENTS_AUDIT.md](AGENTS_AUDIT.md).

Раздел 7 AGENTS.md описывает выбор стека до согласования. После обсуждения заказчик явно утвердил React + TypeScript + Vite, Supabase/PostgreSQL, FullCalendar, Cloudflare Pages и Blender → GLB → React Three Fiber/Drei. Это согласование действует; менять выбранный стек при текущей проверке не требуется.

При последующей разработке действуют следующие ограничения AGENTS.md; в текущем интерфейсе эти функции не реализуются:

- Основное планирование и синхронизация бесплатны; базовый питомец и базовая кастомизация тоже. Платной может быть только необязательная косметика.
- Выполнение задачи подтверждает пользователь. Награда за одно выполнение начисляется сервером не более одного раза; окончание Pomodoro само по себе не даёт награду.
- Фиксированные занятия и ручные слоты приоритетны. Пересечения запрещены, нехватка времени показывается явно, а дата, время, дедлайн и часовой пояс учитываются вместе.
- Дробление задач, автоматические перерывы и правила приоритизации требуют отдельного согласования до реализации; утверждение стека не является утверждением этих правил.
- Предполагаемую длительность вводит пользователь; категории и теги необязательны. Плановые блоки и фактические сессии хранятся отдельно, перерывы исключаются из активного времени. Pomodoro и ручной учёт используют один источник времени без двойного подсчёта.
- Рекомендации используют только историю данного пользователя: медиану сопоставимых завершённых задач, начальный ориентир — не менее трёх подтверждённых наблюдений. При малой выборке — «Пока мало данных». Категория, объём и сложность важны; сходства названий недостаточно. Оценки не меняются автоматически, историю времени можно будет исправлять.

Для нынешнего поведения есть `npm test`: Node.js Test Runner, jsdom и загрузка TSX через уже используемый Vite. jsdom — только зависимость разработки и не попадает в сборку сайта. Настоящие проверки алгоритма планирования и учёта времени появятся вместе с этими модулями; тестирование заглушек не выдаётся за тестирование будущей бизнес-логики.
