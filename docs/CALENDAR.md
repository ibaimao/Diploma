# Календарь и ручное размещение

## Использование

- «Неделя» показывает понедельник–воскресенье и сетку времени. Стрелки меняют неделю, «Сегодня» возвращает к текущей. Заголовок дня открывает подробное расписание.
- «Месяц» показывает полный месяц. Стрелки меняют месяц, нажатие даты открывает расписание дня. Переключение режимов сохраняет выбранную дату.
- «Добавить задачу» открывает общую расширенную форму. После сохранения форма закрывается и начинается выбор места. С длительностью нажмите свободное время в неделе или сначала дату в месяце и затем время в расписании дня. Блок равен введённой длительности.
- Без длительности выбирается только дата: время начала и окончания не создаются. В календаре такая задача отображается в строке «Без времени».
- «Отменить размещение» оставляет сохранённую задачу в списке «Незапланированные задачи» над календарём. Кнопка задачи снова запускает выбор места. Уход в другой раздел также не удаляет задачу.
- Нажмите размещённую задачу для редактирования, выполнения, удаления или повторного размещения. Временной блок также можно перетащить мышью или удержанием на сенсорном экране. Изменение длительности пересчитывает окончание блока с сохранением начала, снятие длительности убирает временной блок и сохраняет дату.
- Дедлайн и конфликты проверяются при размещении, переносе и редактировании. При отказе данные остаются прежними. Дедлайн по дате включает весь местный день; интервал может закончиться ровно в следующую полночь.
- «Добавить событие» создаёт фиксированный интервал. Еженедельная серия начинается с выбранной даты. Нажатие события открывает редактирование и удаление; эти операции относятся ко всей серии.
- «Помочь подобрать время» честно сообщает, что алгоритм ещё не реализован. После сохранения можно разместить задачу вручную. Точка интеграции — `assistedPlanning` в `scheduling.ts`.

## Хранение и границы модулей

`App` владеет одним `useTasks` для дневного списка и календаря. Задачи по-прежнему сохраняются в `study-planner.tasks.v2`. Совместимое расширение: `planned_date` теперь может быть `null`, что означает отсутствие размещения; прежние строки даты и все остальные поля сохраняются. Перенос данных v2 не требуется. Миграция v1 с сохранением исходного ключа продолжает работать. Дата выполнения, предполагаемые минуты, временные блоки, дедлайн, приоритет и выполнение остаются независимыми полями.

Фиксированные события хранятся отдельно в `study-planner.events.v1`. Сначала проверяются и сохраняются данные, затем обновляется интерфейс. Ошибки localStorage не изображаются как успешное сохранение; повреждённые данные не перезаписываются. События `storage` обновляют открытые браузерные вкладки. Одновременные записи localStorage из разных вкладок не являются транзакцией; серверной синхронизации в этой версии нет.

`scheduling.ts` отвечает за интервалы, местные даты, повторения, дедлайны и конфликты; `CalendarPanel.tsx` — за бесплатные MIT-компоненты FullCalendar (dayGrid/timeGrid/interaction). Комната, навигация и оформление дневного списка не менялись. Прокрутка остаётся внутри рабочей области. Отменённые задачи не удаляются; искусственная длительность не добавляется. Дробления задач и автоматического планирования нет.

## Проверка и запуск на Windows

Нужен Node.js 24. В PowerShell из каталога проекта:

```powershell
npm ci
npm test
npm run typecheck
npm run build
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).

Дополнительная проверка в Chromium: оставьте `npm run dev` в первом терминале, а во втором выполните:

```powershell
npx playwright install chromium
npm run test:browser
```

Для системного Chromium можно указать `CHROMIUM_PATH`, для другого адреса сервера — `APP_URL`. Browser smoke-test проверяет реальное создание, закрытие формы, размещение через месяц и день, сохранение после перезагрузки, выполнение в двух разделах, еженедельное событие и размеры 320/390/760/1440 px. Скриншоты записываются только в игнорируемый `work/`.
