# Задачи v2: модель, формы и проверка

## Разделение данных

| Поле | Смысл |
| --- | --- |
| `planned_date` | Местная календарная дата дела, `YYYY-MM-DD`. Не время начала и не дедлайн. |
| `deadline` | `null`, `{ kind: "date", date: "YYYY-MM-DD" }` либо `{ kind: "datetime", at: "…Z" }`. |
| `estimated_minutes` | Положительное целое число минут либо `null`, если оценка не указана. |
| `actual_minutes` | Отдельное фактическое время. Формы его не меняют, учёт сессий пока отсутствует. |
| `priority` | `high`, `medium`, `low`, `none`. Цвет не хранится, а вычисляется. |
| `completed` | Выполнение, меняется только действием пользователя. |
| `schedule_blocks` | Будущие интервалы `{ id, starts_at, ends_at }`, при создании пустой массив. |

Дата без времени не преобразуется в фиктивное пользовательское значение «23:59». При проверке просрочки вычисляется последняя миллисекунда выбранного местного дня. День может длиться 23 или 25 часов. Точный дедлайн хранится как момент UTC, вводится и отображается в местном часовом поясе браузера. Без дедлайна задача не становится просроченной только из-за прошедшей даты дела.

Порядок внутри каждой группы — по настоящему дедлайну, без срока в конце. При одинаковых сроках сохраняется исходный порядок. Переключение выполнения не меняет порядок записей в хранилище, поэтому отмена возвращает задачу на прежнее место среди невыполненных.

## Два режима формы

`QuickTaskEditor` из `src/features/tasks/TaskEditor.tsx` используется кнопкой «+» в дневном списке. Дата дела всегда сегодняшняя на момент сохранения; длительность и точное время сегодня опциональны. Приоритет по умолчанию `none` (голубой).

`AdvancedTaskEditor` экспортируется из того же файла и пока используется для редактирования карточки. Для создания будущий календарь может передать `day` — выбранную дату, `onSave(input)` и `onClose()`, не передавая `task`. Для редактирования передаются `task` и, при необходимости, `onDelete()`.

- `onSave` получает общую модель `TaskInput` и возвращает `true` только после успешного сохранения. При `false` форма остаётся открытой с ошибкой.
- При создании используется `createTask(input)`, при изменении — `editTask(current, id, input)`. Изменение сохраняет ID, фактическое время и будущие временные блоки.
- Включённые поля проверяются перед сохранением. Выключенные поля дают `null`, даже если пользователь ранее вводил значения.
- Дата дела и дата дедлайна могут различаться. При переносе дела с сегодняшнего дня карточка перестанет показываться в дневном списке, но сохранится в хранилище.

Календарная вкладка не менялась и не содержит кнопки расширенного создания. Создание в расширенном режиме проверяется автоматическими тестами компонента. Подключение календаря, поиск свободных интервалов и предложения планировщика — следующие этапы. Для будущего автоматического размещения сначала потребуется оценка длительности; `null` нельзя заменять произвольными минутами. Дедлайн нельзя использовать как время начала блока.

## Миграция без потери существующих задач

1. Существующий `study-planner.tasks.v2` читается первым. Пустой массив считается намеренно сохранённым списком и не восстанавливается из v1.
2. Если v2 отсутствует, читается `study-planner.tasks.v1`. Весь список проверяется до записи.
3. ID, названия, категории, выполнение, предполагаемые и фактические минуты и точные дедлайны сохраняются. Для старой модели отдельной даты дела не было, поэтому берётся местный день старого дедлайна. Строка только с датой становится дедлайном вида `date`.
4. Старый цвет переводится в соответствующий приоритет: коралловый → высокий, персиковый → средний, шалфейный → низкий, голубой → без приоритета. Так сохраняется цвет карточки. Это правило совместимости, а не вычисление приоритета по содержанию задачи.
5. Валидный список записывается в v2. Исходный v1 **не изменяется и не удаляется**: он остаётся резервной копией на этом браузере. При ошибке преобразования или переполнении хранилища сохранённые старые записи остаются целыми, UI показывает ошибку.

Для дополнительной ручной резервной копии перед тестированием можно скопировать значение ключа v1 из хранилища сайта средствами своего браузера. Не очищайте данные сайта при проверке миграции.

## Как проверить вручную

На Windows: Node.js 24 LTS, терминал в папке проекта, `npm ci`, `npm run dev`, адрес из терминала.

1. **Пустая просрочка:** если нет незавершённых задач с истёкшим дедлайном, заголовка «Просроченные задачи» и отдельного списка быть не должно.
2. **Быстрое создание:** нажмите «+». Оба тумблера выключены, поля времени скрыты. Введите только название и сохраните. Появится голубая карточка сегодня без подписи выдуманного дедлайна.
3. **Длительность:** включите «Добавить время выполнения». Задайте 1 час 15 минут. Нулевая/отрицательная оценка не должна сохраниться. Выключите тумблер и сохраните — оценка станет `null`.
4. **Точное время сегодня:** включите «Выполнить до определённого времени», выберите время. Даты и прошлых/будущих дней в быстром режиме нет. Пустое время при включённом тумблере не сохраняется. Если время уже прошло, задача сразу попадёт в просроченные.
5. **Редактирование и приоритет:** нажмите название. По очереди выберите высокий, средний, низкий и без приоритета — после сохранения карточка должна стать коралловой, персиковой, шалфейной и голубой. Ручного выбора цвета нет, в том числе для просроченных карточек.
6. **Необязательный дедлайн:** при редактировании включите дедлайн, задайте вчерашнюю дату без точного времени — задача должна стать просроченной. Задайте сегодняшнюю дату без времени — до следующей местной полуночи она не просрочена. Включите точное время, сохраните; затем выключите только точное время — останется дата. Выключите дедлайн целиком — срок станет `null`.
7. **Порядок и выполнение:** создайте две обычные задачи и одну просроченную на сегодня. Завершите обычную — название зачёркнуто, карточка бледнее и ниже всех невыполненных и просроченных. Завершите последнюю просроченную — раздел просрочки исчезнет. Снимите выполнение — задача вернётся в соответствующую группу. Монеты не начисляются.
8. **Сохранение:** после изменения полей и статусов нажмите F5. Карточки, приоритеты, необязательные значения и выполнение должны сохраниться без дубликатов. Удалите все задачи с подтверждением, обновите страницу — примеры не появятся.
9. **Закрытие:** введите несохранённые изменения и нажмите красный крестик или Escape. Они не сохраняются. Нижней «Отмены» нет, сохранение зелёное. При удалении можно вернуться к задаче, не подтверждая удаление.
10. **Только сегодня:** выбора даты над списком нет. Для проверки разделения модели можно при редактировании изменить дату дела на завтра, оставив будущий дедлайн: задача сохранится, но не будет показана сегодня. Просмотр будущих/прошлых дней появится позднее в календаре.
11. **Совместимость:** откройте тот же адрес и профиль браузера, где уже есть задачи v1. Все записи должны преобразоваться один раз; старый ключ останется. Старые выполненные дела не на сегодня остаются в данных, хотя дневная вкладка их не показывает.
12. **Маленький экран:** откройте форму, включите все поля и прокрутите её до кнопки сохранения. Прокрутка должна оставаться внутри окна, крестик доступен. При прокрутке списка комната и навигация не перемещаются вместе с ним. Проверьте также настоящую экранную клавиатуру телефона.

Автоматическая проверка: `npm test`, `npm run typecheck`, `npm run build`. Тесты используют реальный React-код в jsdom; настоящие размеры, сенсорная прокрутка и виртуальная клавиатура требуют браузерной проверки.
